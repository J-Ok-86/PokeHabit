PokéRoutine v1.7.120 — 기록·달력 분석 UI 정리 / 대량 데이터 성능 개선

업데이트 방법
1. 앱에서 전체 사용자 JSON 백업을 먼저 보관합니다.
2. ZIP의 index.html, moves.html, sw.js를 GitHub Pages 저장소의 기존 파일과 교체합니다.
3. PWA를 재실행하여 헤더 v1.7.120을 확인합니다. 캐시가 남아 있으면 새로고침하세요.

변경 ① 기록·달력 분석 체계 정리
- 기록 탭에서 주간 요약·생활 리듬·수면·퀘스트 분석 바로가기를 제공하며, 클릭 시 해당 섹션으로 이동합니다.
- 달력에서 퀘스트 필터를 분석 대상 선택 영역으로 묶고, 선택일 상세 기록을 명확히 구분합니다.
- 공통 분석 그래프 X축을 월/일로 표준화하고, 긴 기간은 간격을 둔 날짜 눈금만 표시합니다.
- 공통 그래프의 Y축 단위/눈금, 미기록(—)과 실제 0의 구분을 유지합니다.
- 320px 화면에서도 기간 버튼과 기록 탭 그래프/필터가 가로로 넘치지 않도록 스타일을 조정합니다.

변경 ② 데이터가 커질 때의 성능
- 화면 한 번을 그리는 동안 퀘스트별 이벤트 이력, 날짜별 완료 기록, 작성 메모/생활 이벤트의 날짜를 한번 인덱싱합니다.
- 퀘스트 생성일·변경 스냅샷·예정일·통계 기간 행을 렌더링 한 번 동안 재사용합니다.
- 달력의 날짜별 상태 계산에 전체 완료 기록 반복 스캔을 없앴습니다.
- 렌더 호출 및 저장시 캐시를 새로 만들어 데이터 수정, 계정 전환, 백업 복원 후 결과가 남지 않도록 합니다.
- 인덱스는 메모리에만 존재하며 JSON 데이터 구조/포인트/경험치/기존 기록을 변경하지 않습니다.

검증
- JavaScript 구문 검사 통과
- 퀘스트 22개 · 완료 기록 약 9,500건 · 메모/생활기록 각 2,000건의 브라우저 테스트
- 수정 전후 예정일·완료 횟수·달성률 비교 일치
- 320/390/760px 월간·연간·기록 탭 렌더링과 가로 넘침 검사
- 실제 Galaxy PWA 전체 장시간 사용·오프라인 복원 시나리오는 별도 확인 필요

그 외 오늘/뽑기/도감/훈련/설정과 퀘스트 보상·저장 로직은 변경하지 않았습니다.
